# Implementer notes

Read this before building a ticket. It covers what the code doesn't make obvious: how to run the checks, how a feature moves from spec to `main`, and the interfaces that later features build on. The spec issues on GitHub hold the requirements, and `GLOSSARY.md` and `docs/adr/` hold the vocabulary and decisions.

## Running the checks

```bash
.venv/bin/python -m ruff check src tests
.venv/bin/python -m pytest -q                 # full suite + coverage
.venv/bin/python -m pytest -q tests/integration/test_graph.py --no-cov   # one file, fast
```

- **Always use `python -m`.** If the virtualenv was created before the project folder was renamed, its `pytest`/`ruff` scripts point at the old path and won't run. Recreate it with `uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -r requirements-dev.txt`.
- **The package is not pip-installed.** `pyproject.toml` sets `pythonpath = ["src"]`, so pytest tests the code of whichever checkout or worktree you run it from. In a git worktree, run the main checkout's `.venv/bin/python -m pytest` from the worktree root.
- **No network in tests.** Fake models at `integrations/llm.py` and search at `integrations/search.py`, either with monkeypatch or with httpx's `MockTransport`.

## From spec to `main`

1. **Spec:** `/to-spec` writes one spec issue per feature.
2. **Tickets:** `/to-tickets` creates them as sub-issues of the spec, with native blocking links. Every user story in the spec maps to one ticket. Each ticket lists its stories under "User stories covered", and the spec has a "Story coverage" comment.
3. **Building:** `/implement-spec #<spec>` creates `feature/<slug>`. Each ticket is built test-first on `ticket/<n>-<slug>` in its own worktree, then merged into the feature branch.
4. **Review:** `/code-review` runs on the feature branch, and the fixes go in one pass.
5. **Merge:** one PR per feature closes the spec and its tickets. `main` is protected (PR required, and CI jobs `test` and `docker` must pass), and merging deploys to Azure (`docs/deployment_guide.md`).

Commit messages end with the `Co-Authored-By` trailer given in the session.

## Interfaces later features build on

**Routing and plans** (#4)
- `workflow/routing.py`, `RoutingDecision`: `intent` (`new_content` / `refine` / `chat` / `unclear`), `topic_name`, `same_topic`, `formats`, `fresh_research`, `refine_target`, `instructions`, the writer options `target_keyword` / `template` / `length` / `length_unit`, `source_piece` / `source_kind` (what a new piece builds on), `reply`, `clarifying_question`, `topic_answer`. The glossary avoids "subject", so use Topic terms.
- **A narrower angle on the active Topic asks the Topic question.** Only a request on the same Topic runs straight away.
- `workflow/formats.py` is the single format table. Each format maps to `FormatSpec(agent, label, kind, options, templates, length_unit)`: `options` are the routing fields its writer step takes, and `plan.writer_options` reads them. Add a new format here, not in parallel maps. Content Pieces keep the field name `kind`.
- `workflow/plan.py` builds plans in code: `build_plan`, `describe_plan`, `replan`. The research-first rule (ADR 0001) lives only in `build_plan`.
- `workflow/graph.py` runs the dispatcher loop. An agent stops the plan by returning `{"abort_reason": reason}`. A writer that fails posts an error, and the plan carries on.

**State and Topics**
- `workflow/state.py` holds `Topic`, `ResearchRecord`/`ResearchSource`, `ResearchBrief`, `ContentPiece`, `Revision`, `PlanStep` and `PendingTopicQuestion`.
- `workflow/topics.py` holds `active_topic`, `create_topic`, `new_piece_id`, `add_piece`, `add_revision`, `piece_topic` and `piece_title`. **Always save Content Pieces and Revisions through `add_piece` and `add_revision`.** Refine finds pieces through each Topic's `piece_ids`, so writing state directly breaks refinement.
- `workflow/progress.py` holds `progress_message` and `is_progress`. Agents post progress through it, which keeps those messages out of the router's ~10-message history window.

**Research and Brief** (#5, #6)
- `integrations/search.py` holds `configured_providers`, `missing_key_names`, `search_with_fallback` and `fetch_page`.
- `workflow/sources.py` holds `merge_sources` and `normalise_url`.
- `workflow/statistics.py` has `is_verified`, and `figures` / `is_grounded`, which LinkedIn's "grounded figures" check uses with the same number matching.
- `workflow/report.py` holds `render_report` and `summary_line`. The Research tab and export (#23) reuse them.

**Quality loop** (#19, reused by #20 and later formats)
- `workflow/quality_loop.py`: a format plugs in as a `QualityFormat(name, draft, revise, checks, judge, finalise, failure)`, and `quality_loop(fmt)` builds the writer's node. `agents/blog_writer.py` (`BLOG = QualityFormat(...)`) and `agents/linkedin_writer.py` (`LINKEDIN`) are the worked examples, each with a `*_REFINEMENT` variant. `quality_text` is the Quality Score block every format's chat message ends with.
- `workflow/content_checks.py` provides the `Draft`, `Post` and `CheckResult` shapes and one function per check. `check_blog` and `check_linkedin` compose them. A new format adds its own `check_<format>`.
- `workflow/quality_score.py` holds `quality_score` and `comparable_points`: checks are worth 70 points and the reviewer 30.
- `agents/quality_judge.py` is the AI reviewer, using the `quality_judge` model in `config/models.yaml`.

**Images** (#21)
- An image step can carry `source_piece` (the image format takes it as an option, resolved by `resolve_source` as for repurposing): `optimise_prompt(..., piece=...)` gets that piece's title and kind, its kind sets the use (`FormatSpec.image_use` in the format table), and the metadata records `ImageMetadata["source_piece"]` (`NotRequired`, absent without a source).
- `agents/image_generator.py`: `optimise_prompt(request, topic, visual_style=None, piece=None)` returns an `ImagePrompt` (`prompt` ending with `NO_TEXT_RULE`, `use`, `aspect`, `alt_text`); `aspect_of` picks the shape; `image_revision(...)` saves the PNG and returns the Revision with its `image` metadata; `image_message(piece_id, revision_number, metadata)` is the chat message, whose `additional_kwargs["content_piece"]` is `{"piece_id", "revision"}` (from 1).
- New and refined images share one path: `_new_image` / `_refine_image` each build an `_ImageJob` (request, optimiser request, source piece, fallback prompt, kept aspect, save function) and `_make_image` runs it. Change the shared steps there, not per path.
- A refine step with a `target` goes to `_refine_image`: it re-optimises from the latest Revision's `image["prompt"]` plus the instructions, gives the optimiser the piece in `image["source_piece"]` again (looked up on the Topic), keeps `image["aspect"]` and any `image["source_piece"]` unless the optimiser returns a new shape, and adds a *refinement* Revision through `add_revision` with its own file (`<piece>-r<n+1>.png`).
- A failed prompt optimisation doesn't stop the image: it is drawn from a plain prompt (the request, or the latest prompt plus the instructions, with `NO_TEXT_RULE`), in the shape `asked_aspect(request)` finds, otherwise the source piece's or latest Revision's, otherwise square. Only a failure after that (saving the file) posts `NO_IMAGE` / `NO_REFINED_IMAGE`.
- `make_image(prompt, aspect, topic_name, colour=None)` returns a `GeneratedImage` and never raises for a failed model: it falls back to a placeholder card (model `PLACEHOLDER_MODEL`, in `colour` or `image.placeholder_colour`).
- **Brand visual style (#55).** `_make_image` reads `active_brand_profile(state).visual_style` for new and refined images alike: `describe_visual_style(style)` (in `workflow/brand_profiles.py`: colours with the primary named, mood, medium, notes) is the optimiser's `visual_style`, and `style.primary` (or `None`) is `make_image`'s `colour`. Default has no colours, so its placeholder uses `image.placeholder_colour`. `optimise_prompt` always takes the profile's style (there is no style in config). Image tests pass `brand_profile_id=` to `run_plan`/`run_refine` in `tests/integration/test_image_generator.py`, which load it through `load_brand_profile`. **Generate images through it, not `llm.generate_image`**, so new and refined images both get the placeholder. `image_revision` sets the `placeholder` flag and `fallbacks` from the `GeneratedImage`, and `image_message` (an `AIMessage`) says when it is a placeholder. The `image` trace has `request`, `optimised_prompt`, `optimiser_failure`, `models_tried` (`GeneratedImage.models_tried()`: the failed models, then the one used, `placeholder` included) and `placeholder`.
- `ImageMetadata` in `workflow/state.py` is the fixed record on `Revision["image"]`. Images have no Quality Score.
- The Chat tab (`web_app/streamlit_app.py`) renders any assistant message with a `content_piece` reference (looked up with `find_revision(state, piece_id, number)` in `workflow/topics.py`) as the image loaded from `file_path`, a caption (`image_caption`: `model · size`, or `Placeholder image · size` when `placeholder` is set), and an "Optimised prompt" expander. A refined image just needs its message to reference the new Revision.
- `workflow/image_files.py`: `image_path(topic_id, piece_id, revision_number)` (`<data>/images/<topic>/<piece>-r<n>.png`) and `save_png`.
- `workflow/image_files.py` also draws the card: `placeholder_png(size, colour, topic_name)`, and owns the chat's wording: `PLACEHOLDER_LABEL`, `size_label(metadata)` (`1536×1024`) and `image_caption(metadata)`. Use them rather than formatting sizes or the label again.
- Config: `image.models`, `image.sizes`, `image.quality`, `image.placeholder_colour`; `ImageOptions.size_for(model, aspect)` and `quality_for(model)`. `HEX_COLOUR` in `core/config.py` is the one `#RRGGBB` pattern.
- Tests: `tests/conftest.py` blocks LiteLLM's image call and points the data folder at a temporary directory for every test.

**Brand Profiles** (#22)
- `workflow/brand_profiles.py`: `BrandProfileStore(folder=None, clock=...)` (by default `<data>/brand_profiles/`, one `<id>.json` per profile) with `list()` (Default first, then by name; bad files skipped with a warning), `get(id)`, `create(fields)`, `update(id, fields)`, `delete(id)` and `duplicate(id, name=None)` (named "<name> copy", numbered until unique). `fields` is a dict or a `BrandProfileFields`/`BrandProfile`; `profile.fields()` gives the editable fields back.
- `BrandProfile` (pydantic) has `id` (a slug that never changes on rename), `name`, `audience`, `tone` (1–6), `dos`, `donts`, `words_to_avoid`, `writing_sample`, `voice_description` (both optional), `visual_style: VisualStyle(colours, mood, medium, notes)` (`.primary` is `colours[0]` or `None`; `medium` is `photo` / `illustration` / `3D` / `flat graphic`), `created_at`, `updated_at` (UTC).
- `DEFAULT_PROFILE` / `DEFAULT_PROFILE_ID` (`"default"`): built in, never a file. `update`/`delete` on it raise; `duplicate` works.
- Errors: `BrandProfileError` with `.field` (a dotted path such as `name` or `visual_style.colours.0`; `None` for the Default guard) and a plain message, e.g. `"tone: can have at most 6"`. `get` raises `BrandProfileNotFound` (a `BrandProfileError`) for an unknown or unreadable id; fall back to Default there.
- **The active Brand Profile (#52).** The sidebar passes `brand_profile_id` into every run as conversation input (`st.session_state.brand_profile_id`, `"default"` for a new conversation). The graph's first node, `load_brand_profile` (`workflow/active_brand_profile.py`), loads it through the store into `state["brand_profile"]` (a JSON dump). A missing id means Default; an id with no saved profile falls back to Default and posts a one-line progress notice once per missing id in a conversation (`missing_brand_profiles_noticed`).
- **Inside an agent, read the profile with `active_brand_profile(state) -> BrandProfile`** (from `workflow/active_brand_profile.py`). Never read the store or the UI from an agent, and never read `state["brand_profile"]` directly. It returns `DEFAULT_PROFILE` when nothing was loaded (an agent unit-tested without the graph), so writers, the reviewer and images (#53–#55) always get a profile.
- **Writers (#53).** `workflow/brand_voice.py` owns which voice fields exist and how they become prompt text: `voice_text(profile)` (name, audience, tone, do's, don'ts, words to avoid and learned voice description; never the writing sample), and `brand_voice(state)` for the active profile. Both writers' `_prompt` include it, so drafts, automatic revisions and refinements all get it. Research, the Content Strategist and the Query Handler don't. Tests: `record_model_calls(monkeypatch)` (after `fake_router`) records every structured call as `(agent, prompt text)`; `prompts_to(calls, agent)` filters them.
- **Revisions record it automatically.** `add_piece` and `add_revision` stamp each new Revision with `brand_profile: BrandProfileRecord` (`{id, name, updated_at}`, from `brand_profile_record(state)`), unless it already has one. Don't set it in the agents. Existing Revisions are never touched, so editing or switching a profile only affects new pieces and refinements.
- **Brand voice in the Quality Score (#54).** The quality loop's judge calls `review(text, criteria, brand_profile)` (`agents/quality_judge.py`; the profile is required and rendered with `voice_text`) with the active profile, so every Review has `brand_voice` and the reviewer's average includes it. A `QualityFormat` gives only `reviewed_text(draft)` and `judging_criteria`; its `checks(state, draft, avoid)` is handed the profile's words to avoid. A new format gets both for free. `quality_text` adds a `**Brand voice:** n/10` line.
- **Words to avoid (#54).** `content_checks.words_to_avoid(text, avoid)` (whole words and phrases, any case; `measured` lists those found, or "none found"). `check_blog(..., avoid=)` and `check_linkedin(..., avoid=)` append it last, and skip it when `avoid` is empty (Default has none). Writers pass on the `avoid` the loop hands their `checks`. A hyphen and a space are the same separator ("game-changer" matches "game changer"), on purpose.
- **Tracing (#54).** Each `<format> attempt` trace also has `brand_profile_id` and `brand_voice`; it is the only trace the writer step emits itself.
- Tests: fake reviewer verdicts must include `brand_voice` (the schema requires it now that a profile is always given). The writer tests' `verdict()` defaults it to the engagement score, so scores are unchanged; `run_plan(..., profile=)` seeds the active profile.
- **The Brand Profiles tab (#56)** is `web_app/brand_profiles_tab.py` (`brand_profiles_tab()`). The form is plain widgets (not `st.form`) keyed `bp_<field>` (`bp_name`, `bp_tone`, ..., `bp_colours`, `bp_medium`); list fields are one per line, colours comma-separated. `fill_form(fields)` puts `BrandProfile.fields()`-shaped values (any subset) into them, and `form_fields()` reads them back for the store. Every action is a button `on_click` callback, so the sidebar picker sees a change on the same rerun; **fill fields from a callback** (e.g. a "Learn voice" button, #57), never after the widgets are drawn. `voice_description` is the `bp_voice_description` text area (#57). Store errors land in `st.session_state.bp_error` as the `BrandProfileError` (`.field`, and `.message`, the text without the field) and show under that field. `BrandProfileStore.copy_name(name)` gives the free "<name> copy" name.
- **Learn voice (#57).** `agents/voice_learner.py`: `learn_voice(sample) -> LearnedVoice(voice_description, tone)` is one `complete_structured` call to the `brand_voice` model (in `config/models.yaml` and `AGENT_NAMES`). The description is under 120 words, `tone` 3–6 descriptors. It raises `LearnVoiceError` (message for the marketer) for a sample outside 300–10,000 characters (no call) or any failed call. The tab's `bp_learn_voice` button fills `bp_voice_description` (now a text area) and `bp_tone` via `fill_form`, unsaved; errors go in `st.session_state.bp_voice_error`, shown under the button.
- Tests: set the profile per run with `graph.invoke({"messages": [...], "brand_profile_id": id}, ...)` (`send_as` in `tests/integration/test_graph.py`); create profiles with `BrandProfileStore()`, which uses the temporary data folder from `tests/conftest.py`. Revisions made in a Default conversation record `{"id": "default", "name": "Default", "updated_at": "2026-10-29T00:00:00+00:00"}`, so exact-match Revision assertions include it.

- Tests: `tests/integration/test_workspace.py` runs the real `build_graph()` with the model faked at `llm.complete_structured` and the temporary data folder. AppTest: set `at.query_params["thread"]` before `run()` to simulate a reload.

**Usage (#24)**
- **Ledger:** `core/usage.py`. `UsageLedger(path)` appends one JSON line per `UsageEvent` to `<data dir>/usage.jsonl` and keeps `.events` in memory; unparseable lines are skipped on load; `.clear()` empties it. `get_ledger()` is the shared instance for the configured data folder (one per path), and `usage.record(event)` is what integration modules call (a write error is logged, never raised). Queries: `select(run_id=, conversation_id=, day=)` and `totals(...)` (same filters, none = all time) returning `Totals(calls, tokens_in, tokens_out, cost_usd, cached, fallbacks, estimated; .tokens)`. Usage-tab queries (#73), all on the in-memory events: `by_agent()`, `by_model()`, `searches_per_provider()` (each a list of `Breakdown(name, calls, tokens_in, tokens_out, cost_usd, avg_latency_s, cached, estimated; .tokens)`, dearest first), `cache_hit_rate()` (None before any call), `recent_runs(limit=20)` (`RunRow(run_id, ts, request, cost_usd, tokens, duration_s, fallback, estimated)`, newest first) and `fallback_events()` (`FallbackRow(ts, agent, failed, used, error)`, newest first). **Run requests:** `record_request(run_id, request)` appends a `{"run_id", "request"}` line to the same file (not an event; `.requests` holds them) and `Workspace._run` calls it for `send` (the message) and `refresh_research` ("Refresh research"); `recent_runs` shows the first line. **Estimated costs** are marked `*` in the tab; `Totals.estimated` / `Breakdown.estimated` / `RunRow.estimated` say when any call's cost was an estimate (#72 sets `UsageEvent.estimated`).
- **Usage tab:** `web_app/usage_tab.py` `usage_tab(workspace)` reads only `Workspace.usage() -> UsageView` (conversation/today/all-time `Totals`, `cache_hit_rate`, `fallbacks`, and the table rows); the app never reads the ledger itself. With no events it shows an info message. Tests: `tests/unit/test_usage_queries.py` (seeded ledger) and `tests/e2e/test_usage_tab.py` (AppTest). Because the Usage tab has captions, e2e tests that read the run caption scope to `at.tabs[0].caption`.
- **Event shape:** `UsageEvent(ts, run_id, conversation_id, agent, kind, model, primary, tokens_in, tokens_out, cost_usd, estimated, latency_s, cached, failed)`. `kind` is `completion` | `image` | `search`; `model` is the model or search provider that answered, `primary` the configured one (`.fallback` is true when they differ or `failed` is non-empty); `failed` is `[{"provider", "error"}]`; `run_id` and `conversation_id` are None outside a run. All fields beyond `ts`, `agent`, `kind` and `model` have defaults, so later tickets (#72 images, searches, estimates and fallback errors; #74 `cached`) fill fields in without a schema change.
- **Call context:** `core/call_context.py`. `run(conversation_id, run_id=None)` is a context manager yielding the run id; `agent(name)` sets the current agent inside it; `current()` returns `CallContext(run_id, conversation_id, agent)`. `Workspace._run` opens the run for `send` and `refresh_research` (both now return the run id), and `workflow/graph.py` opens `agent(...)` around every plan step and the Query Handler. Integration modules read `current()` when recording; agents pass nothing. LangGraph propagates the context into nodes. `integrations/llm.py` records the `agent` it was called with (the model-config key, so the quality loop's reviewer calls are `quality_judge`); `current().agent` is for calls that have no agent argument (search and image, #72).
- **Recording a model call:** `llm._record_completion` runs after every `_complete` (so each structured retry is its own event). Cost is `response._hidden_params["response_cost"]` if present, else `litellm.completion_cost`, else 0; tokens come from `response.usage`. Test fakes of `litellm.completion` should return `usage` and `_hidden_params` like the real response.
- **Fallbacks (#72):** `llm._complete` no longer passes `fallbacks=` to LiteLLM: it loops over the agent's models itself (`litellm.completion(model=m, num_retries=, retry_strategy=, timeout=)`), so each failed model's error is kept on the event as `failed=[{"provider": model, "error": str[:200]}]` and the original exception type propagates when every model fails. `model` on the event and `Reply.model` are the configured model name that answered (not LiteLLM's dated `response.model`), so `event.fallback` is reliable. Tests fake `litellm.completion` and raise for the models that should fail.
- **Backoff and prices (#72), all in `config/models.yaml`:** `llm.retry_strategy` (`constant_retry` | `exponential_backoff_retry`, default the latter) is passed to LiteLLM as `retry_strategy`. `llm.token_prices: {model: {input_per_1k, output_per_1k}}` is used when LiteLLM's cost is missing or 0 with tokens used (`llm._cost` returns `(cost, estimated)`); `image.prices: {model: usd_per_image}` when an image response has no cost; `search.prices: {provider_lowercase: usd_per_search}` (default free, never estimated). A used estimate sets `estimated=True`; an unpriced model with no configured price costs 0 unflagged. A cache hit is always cost 0, not estimated.
- **Images and searches (#72):** `llm._generate` (behind `generate_image_with(..., failed_models=)`) records a `kind="image"` event right after each paid provider answer (also one that then fails `check_image`), with `primary=config.image.models[0]` and the earlier models' outcomes as `failed`; agent is `call_context.current().agent` or `image_generator`. `search.search_with_fallback` records one `kind="search"` event per query: `model` is the provider that answered (`"none"` = `search.NO_PROVIDER` when none did), `primary` the first provider, `failed` the earlier providers' errors, `latency_s` the whole chain; agent defaults to `search` outside a step. research.py's worker pools are `langsmith.utils.ContextThreadPoolExecutor` so searches keep the run and agent.
- **Caption:** `UsageLedger.caption(run_id) -> str | None` (None when the run made no recorded call) builds "This run: $0.043 · 12.4k tokens", plus " · N cached" and " · N fallback(s)" when non-zero, with `format_caption(cost_usd, tokens, cached=0, fallbacks=0)`. `Workspace.run_caption(run_id)` wraps it. The Chat tab keeps the last caption in `st.session_state.run_caption = (thread_id, text)` and draws it with `st.caption` under the messages; it is never a chat message.
- **LangSmith trace (#78).** `core/tracing.py`. Tracing is on only when `LANGSMITH_TRACING` is true **and** `LANGSMITH_API_KEY` is set (`Settings.langsmith_tracing/langsmith_api_key/langsmith_project`, project default `contentblitz`); the LiteLLM `langsmith` callback is gone. `Workspace._run` wraps each run in `tracing.tracing()` (`tracing_context(enabled=True, client=make_client(settings))`, or `enabled=False` so nothing is sent whatever the process env says) and invokes the graph with `tracing.run_config(run_id, conversation_id, brand_profile_id, topic)`: the LangGraph run is the root ("ContentBlitz run", its trace id **is** the ledger run id, tags `conversation:`/`run:`, metadata `conversation_id`, `run_id`, `topic`, `brand_profile_id`). The Topic is the one active when the run starts; the Query Handler span's `plan`/`topic` metadata has the Topic the run settled on. Plan steps are its children. Integration modules open provider spans with `tracing.span(name, run_type, inputs=, metadata=)` (a `langsmith.trace`; it nests under the current step and costs nothing when tracing is off): `"<agent> model call"` (llm; metadata `model`, `tokens_in`, `tokens_out`, `cost_usd`, `cache_hit`; #74 sets `cache_hit` via `_hidden_params["cache_hit"]`), `"image model call"`, `"search: <provider>"` (retriever; one per provider tried), `"fetch page"`. `tracing.annotate({...})` adds metadata to the span you are running in; the Query Handler uses it for `routing_decision` and `plan`. Trace metadata from earlier specs is unchanged (`research searches`, `research brief`, `<format> attempt` with the Quality Score, `image`). Worker threads must use `langsmith.utils.ContextThreadPoolExecutor` (research does) or their spans and call context are lost. Tests: `tests/integration/test_langsmith_trace.py` (`RecordingClient` fake; `switch_tracing` sets the env, clears the settings cache and swaps `tracing.make_client`). A new provider call: wrap it in `tracing.span`.
- **Caches (#74).** `core/cache.py` is the one place for cache names, folders and options: `CACHE_NAMES` (`model_responses`, `search`, `page_text`, `research_brief`), `options(name, config=None) -> CacheOptions(enabled, expiry_hours, .expiry_seconds)`, `cache_dir(name, config=None)` (`<data>/<cache.folder>/<name>`, not created) and `cache_dirs()` (all of them, for Clear cache #77). Config is the `cache:` section of `models.yaml` (`CacheConfig`): `folder`, then `enabled` + `expiry_hours` per cache (defaults 24 h model responses, 24 h search, 168 h page text, none for the Brief: `expiry_hours: null`). **#75 and #76 read their switch, expiry and folder from there**, not their own settings.
- **Model response cache.** `llm._configure_cache(config)` runs in `_complete` and sets LiteLLM's global `litellm.cache` (disk, folder + ttl from config) or `None` when switched off; it rebuilds when the folder, switch or expiry changes. LiteLLM caches completions only, never `image_generation`, so don't add image calls to its supported types. A hit is `response._hidden_params["cache_hit"]`; `_record_completion` then sets `cached=True` and `cost_usd=0` (LiteLLM still prices a hit). Needs `litellm[caching]` plus `fastapi` and `soundfile` in requirements (a hit imports `litellm.proxy`).
- **Testing the cache.** Patching `llm.litellm.completion` bypasses the cache. Fake below it with a `CustomLLM` provider (`litellm.custom_provider_map`, see `tests/unit/test_model_cache.py`; define `acompletion` too, fallbacks need it). Expire entries by patching `diskcache.core.time`. `tests/conftest.py` resets `litellm.cache` per test and the data folder is per test, so caches never leak between tests.
- **Research Brief cache (#76).** `workflow/brief_cache.py`: `cached_brief(record, instructions)` and `store_brief(record, instructions, brief)` wrap a `diskcache.Cache` in `cache_dir("research_brief")`, off when `options("research_brief").enabled` is false (nothing is created). `brief_key(record, instructions, models)` is a SHA-256 of each Source's url/title/site/snippet/page text, the step's instructions and the Strategist's configured models (primary + fallbacks, so a config change misses). No expiry. `content_strategist` checks it before drafting and stores only a Brief that survived grounding; a hit makes no model call (and records no usage event). `close_all()` closes open handles (tests use it as "a new process"). Identical research now yields the same Brief, so a test that wants a *rebuild* changes the step's instructions or switches the cache off. Tests: `tests/integration/test_brief_cache.py`.
- **Search and page text caches (#75).** `integrations/search_cache.py`: `get(name, key)` / `put(name, key, value)` over a `diskcache.Cache` in `cache_dir("search" | "page_text")`, off when `options(name).enabled` is false (nothing created); each entry stores its save time and expires per `options(name).expiry_seconds` against the module-level `clock` (tests monkeypatch `search_cache.clock`); `normalise_query`; `close_all()` closes the handles (call it alongside `brief_cache.close_all()` in Clear cache #77, which also deletes `cache.cache_dirs()`). `search.search_with_fallback` tries each provider in order: cache hit on `(provider name, normalised query, max_results)` answers (recorded as a search event with `cached=True`, cost 0, no provider call), else the live answer is cached when non-empty (failures and empty answers never are). `search.fetch_page(..., fresh=False)` caches readable text by URL (stored up to `MAX_PAGE_BYTES`, cut to the caller's `max_chars` on the way out; "" is not cached). **`fresh`** (the research step's *fresh* flag, passed by `agents/research.py` to searches and `fetch_page`) skips the lookup, calls the provider and overwrites the entry. Tests: `tests/unit/test_search_cache.py`. Research tests that rerun identical queries on one provider now hit the cache; change the provider or use `fresh`.
- Tests: ledger unit tests on a temporary file (`tests/unit/test_usage_ledger.py`); the data folder is already temporary per test (`conftest.py`), so `get_ledger()` in a test sees only that test's events. Graph tagging: `tests/integration/test_usage_tagging.py` (imports helpers from `test_blog_writer`).

**Model calls** (ADR 0002)
- Model calls go only through `integrations/llm.py`: `complete`, `complete_structured`, `complete_structured_reply`. After a second invalid reply they raise `StructuredOutputError`.
- Images: `generate_image(prompt, aspect)` tries the image models in config order, skipping one whose provider has no API key, and rejects a result that fails `check_image` (PNG/JPEG/WebP, both sides ≥ 512 px, not nearly one colour across the RGB channels). It returns a `GeneratedImage(data, model, provider_url, fallbacks)`, where `fallbacks` is a tuple of `ModelOutcome` (`{"model", "outcome"}`, also what `ImageMetadata["fallbacks"]` holds), or raises `NoUsableImage` (with `.fallbacks`) when every model fails. `generate_image_with(model, prompt, aspect)` calls one model, unchecked, and raises `ImageGenerationError` for no image.
- Each agent's model and fallbacks are in `config/models.yaml`. Thresholds are in its `quality` section.

## Conventions

- Match the existing style: short module docstrings that cite the spec, few comments, type hints, TypedDict/pydantic shapes, and ruff line length 100.
- Use glossary terms in names, tests and user-facing text.
- Keep echo mode working: with no `OPENAI_API_KEY`, the Query Handler echoes the message. The deployed app's smoke test relies on it.
